# Импорт пакетов YAML

Готовый полный пример: [examples/package.yaml](../examples/package.yaml). Импортер не читает Obsidian, внешние файлы или URL. Астрономические данные для систем готовит dev-скрипт `scripts/fetch-star.mjs` (SIMBAD); приложение внешние сервисы не вызывает.

## Как импортировать

1. Войти в административный раздел и открыть «Импорт YAML».
2. Выбрать `.yaml`/`.yml` либо вставить текст.
3. Нажать «Проверить пакет»: сервер проверит поля и связи, покажет состав будущего черновика. Проверка не сохраняет данные.
4. Нажать «Импортировать черновик» и подтвердить действие.
5. Проверить пакет в обычном редакторе. Опубликовать его отдельно, когда сведения получит экипаж.

Новый `package.key` создаёт новый пакет. Повторный ключ обновляет **весь существующий черновик**, включая его метаданные и ручные правки. Файл — полное желаемое содержимое пакета, а не частичная заплатка. Записи, отсутствующие в новом файле, исчезают из черновика. Их опубликованные версии сохраняются. Для настоящего удаления опубликованного объекта используется раздел `remove`.

Опубликованный пакет с тем же ключом импортировать повторно нельзя. Для следующего поступления создать файл с новым `package.key`, оставляя ключи изменяемых объектов прежними. Пакет за 2146 год можно импортировать и опубликовать заранее: игроки не увидят его, пока дата кампании не дойдёт до даты получения. Импорт не меняет дату кампании и ничего не публикует автоматически.

Если пакет или опубликованные сведения изменились после проверки, сервер вернёт конфликт. Текст останется в форме; нужно нажать «Проверить пакет» ещё раз. Изменение самого YAML также сбрасывает предыдущую проверку.

## Минимальный файл

```yaml
version: 1
package:
  key: expedition-2061
  title: Архив экспедиции
  receivedDate: "2061-01-01"
categories:
  - key: technologies
    name: Технологии
articles:
  - key: information-networks
    category: technologies
    title: Информационные сети
    body: |
      Основной текст статьи в Markdown.

      Следующий абзац.
```

## Общие правила

- Кодировка UTF-8, один YAML-документ, `version: 1`.
- Максимальный размер 8 MiB, от 1 до 5000 изменений суммарно.
- Использовать пробелы для отступов; многострочный Markdown писать через `|`.
- Неизвестные поля и повторяющиеся ключи отклоняются. Якоря `&`, ссылки `*`, явные теги YAML и склейка документов через `---` не поддерживаются.
- Необязательные разделы `categories`, `articles`, `systems`, `routes`, `remove` по умолчанию пусты.
- Игровые даты — строки `YYYY-MM-DD`; лучше явно заключать их в кавычки. `null` означает неизвестное значение.

### Ключи и ссылки

`key` — постоянное имя объекта, до 120 символов ASCII: буквы, цифры, `.`, `_`, `-`; первый символ — буква или цифра. Ключи чувствительны к регистру. Название и текст можно менять, ключ нужно сохранять.

Ключ глобален **внутри типа**: `system.key: sol` в следующем пакете обновляет прежнюю систему. Переименование ключа создаёт другую сущность. Разные категории с одинаковым key объединяются в одну идентичность, поэтому для независимых объектов используйте разные ключи. Для личных наборов удобно добавлять префикс.

Ссылка — key объекта нужного типа либо UUID существующего объекта из административного раздела. UUID можно использовать и как key записи, чтобы обновить ранее созданный вручную объект. Ссылка на имя объекта не поддерживается. Ссылки вперёд работают: статья может ссылаться на другую статью или категорию ниже в файле. Можно ссылаться на уже импортированные ключи из предыдущих пакетов.

Итоговое состояние должно содержать все объекты, на которые есть ссылки. Категории не должны образовывать циклы, маршрут должен соединять две разные системы. Одна сущность одновременно редактируется только в одном черновом пакете.

## Шапка `package`

| Поле            | Обязательность / значение по умолчанию                          |
| --------------- | --------------------------------------------------------------- |
| `key`           | Обязательно; постоянный ключ пакета                             |
| `title`         | Обязательно; до 200 символов                                    |
| `receivedDate`  | Обязательно; дата получения сведений экипажем                   |
| `publicSummary` | Пустая строка; описание для публичного журнала после публикации |
| `source`        | Пустая строка; общий источник для записей                       |
| `effectiveDate` | `null`; общая дата актуальности записей                         |

У любой записи в `categories`, `articles`, `systems`, `routes` и `remove` можно переопределить `source` и `effectiveDate`. Пропущенное поле наследует значение шапки; явный `effectiveDate: null` означает неизвестную дату.

## Категории `categories`

| Поле          | Обязательность / значение по умолчанию  |
| ------------- | --------------------------------------- |
| `key`, `name` | Обязательны                             |
| `parent`      | `null`; key/UUID родительской категории |
| `order`       | `0`; целое число для сортировки         |

## Статьи `articles`

| Поле              | Обязательность / значение по умолчанию     |
| ----------------- | ------------------------------------------ |
| `key`, `title`    | Обязательны                                |
| `category`        | Обязательно; key/UUID категории            |
| `body`            | Обязательно; Markdown, до 1000000 символов |
| `relatedArticles` | `[]`; список ключей/UUID связанных статей  |

Raw HTML в статье не выполняется: действующий Markdown-рендерер экранирует его.

## Системы `systems`

| Поле                 | Обязательность / значение по умолчанию                                      |
| -------------------- | --------------------------------------------------------------------------- |
| `key`, `name`        | Обязательны                                                                 |
| `astronomy`          | `null`; без координат система доступна через список, но не размещается в 3D |
| `faction`            | `null`; принадлежность                                                      |
| `worldClass`         | `unknown`; `central`, `middle`, `outer`, `uncolonized`, `unknown`           |
| `population`         | `null`; целое неотрицательное число                                         |
| `economy`, `anchors` | `null`; текст                                                               |
| `description`        | Пустая строка                                                               |
| `article`            | `null`; key/UUID статьи                                                     |

Если `astronomy` указан, нужны все его поля: `designation`, `raDegrees` (0 ≤ RA < 360), `decDegrees` (−90 ≤ Dec ≤ 90), `distancePc` (≥ 0), `spectralType` (строка или null), `catalogSource`, `epoch`. Это реальные астрономические данные со своим источником, а не игровые предположения.

## Маршруты `routes`

| Поле               | Обязательность / значение по умолчанию                         |
| ------------------ | -------------------------------------------------------------- |
| `key`              | Обязательно                                                    |
| `from`, `to`       | Обязательны; ключи/UUID разных систем                          |
| `type`             | `secondary`; `main`, `secondary`, `experimental`, `historical` |
| `status`           | `unknown`; `open`, `closed`, `dangerous`, `unknown`            |
| `direction`        | `both`; `both` или `forward` (from → to)                       |
| `operator`         | `null`; текст                                                  |
| `minimumJumpOrder` | `null`; целое неотрицательное число                            |
| `description`      | Пустая строка                                                  |
| `article`          | `null`; key/UUID статьи                                        |

## Снятие с публикации `remove`

```yaml
version: 1
package:
  key: navigation-update-2061
  title: Обновление навигационных сведений
  receivedDate: "2061-06-12"
remove:
  - kind: route
    key: old-corridor
  - kind: system
    key: old-system
```

`kind`: `category`, `article`, `system` или `route`; `key`: ключ/UUID существующего ранее опубликованного объекта. Удаление применяется только после отдельной публикации пакета. Зависимые маршруты и статьи нужно удалить или перенаправить в том же пакете; иначе импорт отклоняется целиком. Один объект нельзя одновременно добавить/изменить и удалить.

## Границы API

Административные JSON endpoints: `POST /api/admin/import/preview` с `{ yaml }`; `POST /api/admin/import` с `{ yaml, expectedPackageId, expectedPackageRevision }`. Preconditions берутся из preview (`packageId`, `expectedPackageRevision`); для нового пакета оба равны null. Оба запроса требуют административной сессии. Сами YAML-файлы на сервере не сохраняются.
