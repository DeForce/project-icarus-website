# 0012 — Нормализация масштаба 3D-карты звёзд

## Намерение и зачем

3D-план (`StarScene.client.vue`) строит позиции в реальных парсеках: Sol в нуле,
LHS 1140 — в ~15 единицах (14.96 пк). Фиксированная сетка `GridHelper(20, 20)`
покрывает только ±10 единиц от Сола, поэтому дальняя система висит за пределами
сетки, а камера, подогнанная под самый дальний маркер, превращает локальную
окрестность Сола в точку. Карта должна оставаться читаемой при любом наборе
дистанций — сейчас это не так.

## Подходы

Рассматривались три варианта:

1. **Нормализация контента под фиксированную сетку (выбран владельцем).**
   Позиции систем линейно масштабируются так, чтобы самая дальняя попадала
   внутрь сетки. Пропорции между системами сохраняются, сетка остаётся
   постоянным «эталоном», масштаб пересчитывается при любом изменении данных.
2. Логарифмический/корневой скейлинг — оправдан только при десятках систем
   на дистанциях 5–500 пк одновременно; сейчас это искажение без выгоды.
3. Сетка под контент (реальный масштаб сохраняется) — сетка теряет смысл
   линейки, визуально почти то же, что вариант 1, только хуже.

## Цели

- Все системы с координатами всегда влезают в сетку с визуальным запасом
  (маркер + подпись не наползают на край).
- Пропорции расстояний между системами линейны внутри текущего набора данных;
  сетка не пересоздаётся и не меняет размер.
- Реальные парсеки никуда не исчезают: в карточке системы и списке по-прежнему
  показываются исходные значения.
- Поведение пересчитывается автоматически при добавлении/удалении систем
  (без правок компонента).

## Не-цели

- Изменение домена, API `/api/public/map`, форматов контента.
- Логарифмический скейлинг, сжатие расстояний, «умная» раскладка.
- Фоновый звёздный кластер, подсветка маршрутов, иные визуальные доработки
  сцены (обсуждались отдельно, не входят в этот план).

## Анти-цели

- Поломка e2e-карт: пользовательские сценарии карты (выбор системы, фильтры,
  fallback без WebGL) должны продолжить работать без изменений.
- Хранение масштаба в БД или в данных пакетов — скейлинг чисто презентационный,
  на стороне клиента.

## Ограничения

- Только `StarScene.client.vue` и, при необходимости, чистая функция скейлинга
  в `app/utils/` с unit-тестом (по образцу существующих утилит карты).
- Сетка остаётся `GridHelper(20, 20)`, центр сцены — Sol (гелиоцентрический
  нуль координат).

## Design

1. В `StarScene.client.vue` после вычисления всех позиций считается
   `maxDistance = max(|position|)` по системам с координатами.
2. Коэффициент `scale = FIT_RADIUS / maxDistance`, где `FIT_RADIUS` — константа
   ≈ 8.5 (сетка ±10, запас на радиус маркера 0.09 и подпись). При `maxDistance = 0`
   (все системы в нуле или координат нет) — `scale = 1` как вырожденный случай.
3. Все позиции маркеров, подписей и линий маршрутов умножаются на `scale`.
   Размеры маркеров, размер сетки и поведение камеры (`fitInitialCamera`,
   `centerOn`, `resetView`) не меняются — они уже работают в координатах сцены.
4. Формула вынесена в чистую функцию (например `app/utils/map-scale.ts`)
   с unit-тестами на: типичный набор (Sol + LHS 1140), одиночную систему
   в нуле, вырожденный ноль, пересчёт при добавлении более дальней системы.
5. Утилитный тест-пакет `content/content.test.ts` и спам-пакеты не затрагиваются.

- `npx playwright test` — зелёный (e2e карты без изменений).
- Ручная проверка на dev-сервере: LHS 1140 внутри сетки, Sol у центра,
