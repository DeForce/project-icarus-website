# 0014 — Package Content View

Status: Implemented.
Date: 2026-11-05.

## Intent

Админ должен видеть, что в пакете, в любой момент: игроки могут не видеть
пакет (дата кампании не наступила), но «посмотреть, что залито» — базовая
админская потребность. Сейчас тело редактора обёрнуто в `v-if="isDraft"`
(`app/pages/admin/packages/[id].vue:191`): для опубликованного пакета
остаётся только строка статуса, списка изменений нет. Дополнительно
публичная страница пакета рисует изменения plain-текстом без ссылок
на материалы.

## Scope and constraints

- Админка: read-only список изменений для опубликованных пакетов +
  секция «Просмотр», рендерящая материалы самого пакета (статьи как
  документы через существующий `MarkdownBody`), для черновиков и
  опубликованных, игнорируя `currentDate` кампании.
- Игроки: страница пакета и журнал остаются датно-фильтрованными
  (`receivedDate ≤ currentDate`) — не меняем.
- Публичная страница пакета: названия изменений становятся ссылками
  (статья → `/archive/:id`, система → `/map?system=:id`, категория →
  `/archive`, маршрут → `/map`).
- Без «машины времени»: просмотр покрывает только материалы самого пакета,
  не снапшот мира на дату получения — отдельная задача, если понадобится.
- Без новых зависимостей; идентификаторы и документация на английском,
  игроко-видимый текст — через `i18n/locales/ru.json`.

## Design

### Рассмотренные подходы

1. Только read-only список для опубликованных — не закрывает «полный
   просмотр как админ».
2. **Список + просмотр материалов пакета в редакторе (выбран)** —
   один экран, данные уже грузятся; снапшот-проекция не нужна:
   материалы пакета — это payload его change-строк.
3. Отдельная страница `/admin/packages/:id/preview` — дублирует
   навигацию и данные редактора без выигрыша.

### Решение

- `app/pages/admin/packages/[id].vue`:
  - Для опубликованных — read-only список изменений (тип, название,
    операция) теми же стилями, что у черновика, без кнопок.
  - Для всех статусов — секция «Просмотр» (`<details>` или якорная
    секция): статьи-пакета (`operation === 'upsert'`, `kind === 'article'`)
    рендерятся `MarkdownBody` (title + bodyMarkdown); категории, системы,
    маршруты — краткими карточками полей. Удаления (`remove`) — строкой
    в списке без рендера.
- `app/pages/packages/[id].vue`: имя изменения — `NuxtLink` по `kind`
  (см. Scope); удаления не ссылаются.
- i18n: новые строки только в `ru.json`.
- Новых серверных эндпоинтов не требуется: `AdminPackageDetail.changes`
  уже несёт полные payload.

## Limitations

- Просмотр покрывает материалы самого пакета; снапшот мира «на дату
  получения» не реализован (отложено решением подхода 2(а)).
- Карточки не-статей показывают скалярные поля payload без подписей
  (сырые ключи) — приемлемо для служебного просмотра.
